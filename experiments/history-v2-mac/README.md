# Mac speed and source-fidelity accuracy protocol

The user requested both speed and accuracy. The matched synthetic speed suite is described in [MAC-M5-PRO.md](../../MAC-M5-PRO.md). Accuracy uses the existing, frozen [history-v2 battery](../history-v2/README.md): 20 extraction questions, including four source-absent questions, four direct passage summaries, synthesis from those summaries, and an independent control using the original four passages. Two development requests are retained but excluded from held-out scores. Held-out means excluded from prompt development, not known to be absent from training.

[protocol.json](protocol.json) records the Mac adaptation. Original inputs, questions, prompts, evaluator references and all 17 fixture hashes remain unchanged. Gold is hashed for integrity but never parsed or sent by the generator. Each rendered prompt is tokenized before submission and must fit completely with the output allowance and a 256-token margin. There is no source truncation, silent context reduction or CPU fallback.

The common application context is 32,768 tokens, one slot, FP16 K/V, Metal, flash attention, ten threads and batch/microbatch 512. Reasoning and MTP are disabled; generation is greedy with seed 42 and a 2,048-token output cap. The server can reuse common prompt prefixes, which is recorded in returned usage. Model downloads may continue during accuracy generation. Its application latency is consequently separate from the matched synthetic speed measurements.

These model files, context, API and MTP settings differ from the original Evo accuracy profiles. They are configuration-level observations on identical source tasks, not a controlled comparison of hardware or model architecture. Falcon 180B Chat has a supported context of 2,048 tokens, which cannot fit this complete battery plus its output allowance; it is excluded from this battery and still receives the separate capacity and coherence checks. A memory failure on another model is also an explicit exclusion, never an accuracy score.

The subsequent [Evo inventory extension](evo-extension.json) adds nine exact artifacts from the completed remote matrix, pinned in [mac-extra-models.json](../../scripts/mac-extra-models.json). Their SHA-256 and sizes match the published Evo receipts; separate local paths protect same-named files with different hashes. Three Evo artifacts exceed this Mac's physical memory in weights alone and are excluded. Gemma2 uses its supported 8,192-token context: feasible history stages run unchanged, while a full prompt that cannot fit is recorded as `context_excluded` and is never submitted. Such a partial battery cannot be called completion of the full history comparison.

## Source adjudication

Evaluator identity is **Codex (GPT-6), AI-assisted source review, without independent human adjudication**. Read each output against the supplied OCR text and frozen gold references. This measures fidelity to Charles Oman's narrative, including its judgments and OCR, not modern historical truth or general model accuracy. It is a small, deliberately selected battery with one generation per configuration.

Extraction retains the seven original categories: correct, partial, contradiction, unsupported, qualification loss, ambiguous, and no answer. Report all categories out of 20 and source-absent performance separately out of four. The acceptable-variant rules in the frozen gold take precedence over requiring identical wording. Citation support and quotation compliance are separate judgments; a correct answer with a wrong page remains factually correct but has a citation error. Do not assign partial credit a numeric weight or turn these categories into an unexplained binary score.

For each direct summary and both syntheses, preserve a claim ledger with output anchors, source pages, judgment and rationale, plus judgments for all 16 predeclared coverage units. Compound coverage is partial when only some components appear. Omissions are not invented facts. Keep attribution, numeric bounds and reported events distinct from asserted fact. Claim annotation units are not standardized enough to interpret their count as a precision rate across differently sized outputs.

Synthesis claim errors receive a shared error-family ID and an origin: propagated from a parent summary, newly introduced by synthesis, or repeated independently in the full-source control. Report unique families and manifestations separately. Exact copying from a summary can be checked mechanically; source correctness cannot. Word counts, PDF-marker counts, transport status and throughput are descriptive metrics, not a factual judge.

## Reproduce

Run setup and verified downloads as described in the Mac report, then execute each model sequentially on AC:

```sh
python3 scripts/history_v2/runner.py validate
caffeinate -i python3 scripts/history_v2/run_mac.py qwen3-8b
python3 scripts/history_v2/collect_mac.py qwen3-8b
```

The Mac speed, output and accuracy runners share a local GPU lock. Exact requests, timestamped raw stream events, outputs, token counts, finish reasons, timing, memory samples and offload evidence are retained. A changed protocol or an interrupted request requires a new output directory and deliberate recovery; the runner does not silently retry. Completed checkpoints are reusable only when their request fingerprint and protocol receipt match. Collection independently reconstructs requests from frozen fixtures and checks stream/output agreement. Source judgments live in a separate adjudication ledger and do not enter model prompts.

The collector also checks actual streamed runtime sampling settings and disabled speculation. In this pinned release, explicitly passing `--spec-type none` appends to the default `none` entry, producing the observed string `none,none`; both entries disable speculation. This follows the [b10852 argument parser](https://github.com/ggml-org/llama.cpp/blob/050dde50c/common/arg.cpp#L4155) and [speculation initialization](https://github.com/ggml-org/llama.cpp/blob/050dde50c/common/speculative.cpp#L2402). The collector accepts only nonempty lists consisting entirely of `none`, and rejects any active draft or n-gram type. Original runtime strings remain in the evidence.

Nemotron49’s native template overrides the generic `enable_thinking` keyword. Its first development setup emitted reasoning and was stopped during the development stages, before any held-out request. That attempt is retained under [diagnostic evidence](../../results/2026-09-08/mac/diagnostic/nemotron-reasoning-setup). The corrected delivery adapter appends NVIDIA’s documented `/no_think` control to the system message. The native template consumes that control, preserves the original task/system text, and adds an empty think prefix. The runner verifies that rendered prefix before submission, and collection checks the adapter receipt, actual runtime prefix and absence of reasoning output. See [NVIDIA’s mode instructions](https://huggingface.co/nvidia/Llama-3_3-Nemotron-Super-49B-v1_5#quick-start-and-usage-recommendations). No frozen fixture is edited, and the excluded development attempt is not an accuracy result.

Nemotron’s correctly configured 32,768-token run subsequently exceeded the 1 GiB system swap-growth guard during H3 extraction. The [failed configuration](../../results/2026-09-08/mac/diagnostic/nemotron-context32768-memory) retains its requests, partial stages and memory evidence. The separately labeled [16,384-token configuration](../../results/2026-09-08/mac/accuracy/nemotron-49b) completed all 12 requests with the original 2,048-token output allowance and 256-token margin. Its full-source prompt used 13,541 tokens: 13,541 + 2,048 + 256 = 15,845, within the actual context. This is an explicit memory configuration change, not truncation or a score for the failed 32,768-token run.

The legacy timing field `first_visible_seconds` measures the first nonempty streamed content delta, including a delta containing only whitespace. It is not guaranteed to be the first readable word. Exact deltas and timestamps remain available for alternative latency calculations.

Qwen 122B also exceeded the swap-growth guard with the runtime's default 8,192 MiB RAM prompt cache, first at 32K and then at 16K context. The cache retained several GiB of old prompt states, reaching 7,326.41 MiB in the 16K attempt. A declared `--cache-ram-mib 1024` configuration completed all 12 requests at 32K context, while preserving the frozen prompts, FP16 KV, sampling and output budget. Its actual cache limit is verified from the runtime log and retained in the protocol and load receipts. The [failed configurations](../../results/2026-09-08/mac/diagnostic) include source reviews of completed outputs, and the [successful configuration](../../results/2026-09-08/mac/accuracy/qwen35-122b-iq2xxs) includes all outputs and adjudication. This RAM cache is distinct from GPU KV storage and live-slot prefix reuse; memory figures must not be added as independent pools.

To evaluate the user's above-40-visible-token target, `scripts/history_v2/retokenize_mac.py` processes saved outputs with the same pinned GGUF vocabulary using llama-tokenize's vocabulary-only mode. It does not run inference. It preserves exact content bytes, disables BOS/EOS insertion, escape conversion and special-token parsing, and retains token IDs and output hashes. The visible-phase estimate is retokenized tokens divided by last-minus-first nonempty content-delta arrival time; first readable-delta latency and total-wall rates are also reported. Formatting whitespace is included. These boundary-based stream rates are distinct from API completion counts, server prediction rates, synthetic speed and the Evo SDK metric. The [visible-speed table](../../results/2026-09-08/mac/accuracy/README.md#visible-output-speed-and-the-40-token-target) excludes development requests and keeps accuracy judgments separate.
